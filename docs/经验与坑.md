# 经验与坑（2026-08-17 云端 DoH 全程复盘）

> 目标：以后改这个项目/类似项目，**先读这份文档**，不重复犯错。

## 1. 测试脚本的 DNS 包必须带 0 终止符

`build_q` 构造查询包时，**域名标签后必须显式加 `\x00` 终止符**，再拼 type/class：

```python
for label in name.split("."):
    q += bytes([len(label)]) + label.encode()
q += b"\x00" + struct.pack(">HH", qtype, 1)   # ← \x00 不能省
```

- 缺 0 终止符 → type 偏移错位 → qtype 解析成 256 → 所有分支不执行 → "全空"假象
- **这次的"qt=256 / 全空 / 没注入"有一大半是测试脚本 bug，不是 worker 的问题**
- 教训：先验证测试脚本（本地打印包 hex + qtype），再怀疑线上

## 2. CNAME 链：A/AAAA 记录的 owner 必须是 CNAME 目标

YouTube 视频域名（`rr5---sn-xxx.googlevideo.com`）的解析是 CNAME 链：

```
rr5---sn-xxx.googlevideo.com  CNAME →  rr5.sn-xxx.googlevideo.com
rr5.sn-xxx.googlevideo.com    AAAA  →  2607:f8b0:4004:36::a
```

- **AAAA 记录的 owner name 必须是 CNAME 目标**（rr5.sn-xxx），不能是查询名
- `makeRR` 之前**硬编码 0xC00C**（压缩指针指向查询名）→ 所有记录 owner=查询名 → 浏览器丢弃（CNAME 域名不能有 AAAA）→ 视频连不上
- 修复：`makeRR` 用传入的 nameWire（完整编码）+ `jsonToAnswers` 跟踪 CNAME 链
- **症状**：gateway 直连能播、经 worker 转发不能播；响应 hex 里 AAAA 记录 name=c00c

## 3. 上游查询：JSON 格式 vs wire 格式

CF Gateway（Zero Trust）的 DoH：
- **wire 格式**（`?dns=base64` 或 POST）→ **走 Zero Trust 策略**（返回策略处理的 IP）
- **JSON 格式**（`?name=&type=`）→ **不走策略**（返回普通解析，可能被墙 IP）

- 浏览器直连 gateway 用 wire → 能播；worker 转发用 JSON → 返回被墙 IP → 不能播
- 教训：上游查询统一用 **wire 格式**（标准 DoH），不要用 JSON 参数

## 4. 部署传播延迟（CF Workers）

- `wrangler deploy` 成功后，**边缘节点 1~2 分钟才切到新版本**
- 部署后立刻测试会测到旧版（误判"部署没生效"/"代码坏了"）
- 教训：**部署后等 60~120 秒再测**；用 `wrangler deployments list` 确认活跃版本

## 5. Buffer 兼容性（CF Workers vs Node）

- CF Workers **有** Buffer（polyfill，基于 Uint8Array），但**行为与 Node 有差异**：
  - `buf[pos]` 原生索引 OK；`buf.data` 不存在（那是自定义 polyfill 的）
  - `readUInt16BE` 等有时不可靠 → **手动字节操作**（`(b[x]<<8)|b[x+1]`）最稳
- decodeName/qtype 读取一律纯 Uint8Array 手动解析
- 教训：DNS 编解码**不依赖 Buffer 方法**，用手动字节操作

## 6. EdgeOne Pages：放弃（浪费时间金钱）

- 折腾数小时：路由（[[default]] 不生效/edgeone.json 干扰）、部署（CLI 项目 vs Git 项目混乱）、区域（global 含大陆需备案）
- 结论：**用 Cloudflare Workers（熟悉、文档全、D1 现成）**
- EdgeOne 的教训：`--area overseas`（不含大陆）才能免备案；但整体不值当

## 7. 凭证管理（自己存好自己找）

- **全部凭证集中** `/root/.credentials/`：
  - `cf-token`：CF_DNS_TOKEN / CF_ZONE_ID / CF_ACCOUNT_ID / CF_ZT_TOKEN / **CF_GLOBAL_API_KEY** / CF_EMAIL
  - Global API Key 认证：`X-Auth-Email` + `X-Auth-Key`（不是 Bearer）
- Turso：`/root/.turso-token`；OCI：`/root/.oci/`
- 教训：用户给过的东西要存好记位置，别丢

## 8. 视频域名必须走 IPv6（谷歌 IPv4 全段封）

- googlevideo.com / c.youtube.com：**IPv4 全段被墙**（漏的也立马封）
- 处理：**强制 IPv6**（A 清空 + AAAA 透传）—— 浏览器只拿 IPv6 → 能连
- 用户实测：gateway 直连能播（IPv6 段大陆可达）；指定 IPv4 = 不可用

## 9. 谷歌全家桶（override 组）

- 静态域名（youtube.com / gstatic.com / googleapis.com / ytimg.com 等 36+ 域名）
  → 阿里云专用 IP（47.103.34.63 / 121.43.186.252 等 7 个，AS37963）
- googlevideo 等锁 IP 域名 **不能指定**（只能 IPv6/转发）
- 配置存 D1 overrides 表（改库即生效）

## 10. D1 驱动配置（用户核心要求）

- **改配置 = 改数据库 = 立即生效**（60s 缓存），**绝不改源码重新部署**
- 管理端：admin API（/admin/override /admin/upstreams /admin/config）+ admin UI
- 教训：配置（上游/规则/覆写组）一律存 D1，不要写死在 worker.js

## 11. ECH 注入要点

- ech= 从 cloudflare-ech.com 的 HTTPS 记录获取
- 解析格式：`ech="..."`（alidns 带引号）**和** `ech=AEX+...`（无引号，1.1.1.1 格式）**都要支持**
- 强注 ECH 仅对 CF 托管域名（AS13335 判定）；x.com/AO3 依赖它（SNI 加密不被重置）
- 谷歌域名**不注入**（走阿里云 IP 直连）
